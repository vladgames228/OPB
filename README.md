# olx-bot

Телеграм-бот, отслеживающий сохранённые поиски на olx.uz и присылающий новые
объявления (фото группой, текст, цена, контакт отдельно, ссылка на источник).

## Запуск

1. Скопируй `.env.example` в `.env`, впиши `BOT_TOKEN` (от @BotFather) и свой
   `ALLOWED_USER_IDS` (узнать id можно у @userinfobot).
2. `docker compose up -d --build`
3. В телеграме: `/add https://www.olx.uz/nedvizhimost/kvartiry/arenda-dolgosrochnaya/tashkent/q-xxxxxxx`

Команды: `/add <url>`, `/list`, `/remove <id>`.

При первом `/add` бот берёт текущие объявления как базовую линию и не
присылает их — только то, что появится после.

## Важное ограничение

Я писал парсер (`olx_parser.py`) без доступа к сети, то есть не смог открыть
живую страницу olx.uz и свериться с её реальной вёрсткой. Код пробует два
способа парсинга (JSON из `__NEXT_DATA__`, затем CSS-селекторы вида
`data-cy="l-card"`, типичные для сайтов OLX Group), но названия полей или
классы на olx.uz могут отличаться.

Если после `/add` бот пишет "Найдено сейчас 0 объявлений" или не присылает
новые — вёрстку нужно проверить руками:

```
docker compose exec olx-bot python olx_parser.py debug "https://www.olx.uz/..."
```

Это сохранит HTML страницы в `data/debug.html`. Дальше нужно посмотреть,
как там называется JSON-блок с объявлениями или CSS-классы карточек, и
поправить `_find_ads_in_json` / `_parse_search_html_fallback` /
`_parse_ad_html_fallback` в `olx_parser.py` под реальную структуру.

Телефон продавца на OLX часто подгружается отдельным API-запросом после
нажатия "показать телефон" — простой HTML-фетч может его не увидеть. В
таком случае бот пришлёт объявление с пометкой "контакт не удалось
извлечь" и ссылкой на источник.

## Структура

- `bot.py` — телеграм-бот (aiogram 3), команды и планировщик опроса
- `olx_parser.py` — скрапинг страницы поиска и страницы объявления
- `storage.py` — sqlite: сохранённые поиски + id уже увиденных объявлений
- `docker-compose.yml`, `Dockerfile` — запуск
